# Problem Description (问题描述)
目前的 `MarketService.buyDeck` 方法存在一个 **Bug**：
用户点击购买同一个卡组多次，系统会重复扣款（如果有余额系统的话）并重复创建多个相同的卡组到用户的 `flashcard_deck` 表中。
**需求**：我希望限制用户**只能购买同一个 VIP 卡组一次**。如果用户已经拥有该卡组，再次点击购买时应提示“您已拥有该卡组，无需重复购买”。

为了准确识别用户是否买过某个特定的商品，我需要你帮我执行以下 **"架构级修复"**：

1.  **数据库变更**:
    -   在 `flashcard_deck` 表中新增一个字段 `source_market_id` (BigInt, Nullable)。
    -   该字段用于存储购买源的 ID。如果是用户自建的卡组，该字段为 NULL；如果是从商店购买的，则存储对应的 `sys_market_deck.id`。

2.  **后端逻辑增强**:
    -   修改 Entity (`FlashcardDeck`) 和 Mapper (`FlashcardDeckMapper`) 以支持新字段。
    -   在 `MarketService.buyDeck` 中增加**前置检查**：

        -   如果存在，抛出自定义异常 `BusinessException("您已拥有该卡组")` 或返回特定错误标识。
        -   如果不存在，继续执行复制逻辑，并在插入新的 `FlashcardDeck` 时，将 `source_market_id` 设为当前的商品 ID。

3.  **前端反馈**:
    -   确保 Controller 层能捕获这个错误，并将错误信息传递给 JSP 页面（例如通过 `RedirectAttributes` 的 `addFlashAttribute`）。
